# Практика 2. Анализ безопасности РПО

**Продолжительность: 10 минут.**

## Задание

Исправить построение SQL-запроса в изолированной SQLite-базе в памяти.

## Исходные материалы

- [Материалы практики](data/02-software.md).

Данные в файлах вымышленные и подготовлены для занятия. Работа выполняется локально по выданным материалам; развёртывание инфраструктуры в регламент практики не входит.

Код приведён в Markdown. Для запуска скопировать его в локальный `exercise_sql.py` и выполнить `python exercise_sql.py`.

## Методика выполнения

1. Открыть код и найти объединение SQL с пользовательским вводом — 1 мин.
2. Предсказать результаты обычного имени и специального ввода — 2 мин.
3. Запустить файл Python либо прочитать приведённые результаты в паспорте задания — 2 мин.
4. Заменить запрос параметризованным вариантом — 2 мин.
5. Проверить оба входа и заполнить карточку дефекта — 2 мин.
6. Сопоставить вывод с критерием «специальный ввод не расширяет выборку» — 1 мин.

## Подготовка материалов к сдаче

Опасная строка, исправленный фрагмент и таблица двух тестов до и после исправления.

Сохранить результат как `П02_Фамилия.md` по [шаблону протокола](../templates/test-protocol.md). Для изображений использовать подписи: действие, цель, наблюдаемый результат. При работе только с готовым файлом указать его имя и проверенные поля.

## Критерии приёмки

- Указаны объект и применимый критерий.
- Доказательство связано с конкретным выводом.
- Подтверждённое замечание отделено от недостающих сведений.
- Предложен повторный тест.
- Вывод отвечает на поставленное задание.

## Нормативные и методические основания

Н13: ГОСТ Р 56939-2024; Н18: OWASP ASVS 5.0.0; Н12: Методика ФСТЭК России от 05.02.2021; Н17: NIST SP 800-115.

## Режим без Python

В начальной версии обычное имя «Анна» возвращает 1 запись, специальный ввод возвращает 3. Студент исправляет фрагмент на бумаге/в редакторе и описывает ожидаемый повторный результат: 1 и 0. Эти числа относятся только к выданной учебной базе.
