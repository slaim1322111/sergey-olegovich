# Учебный кейс «Кабинет ведущего»

Объект этой работы — клуб настольных игр «В гостях у троллей». [Общая учебная легенда](../1%20%D1%82%D0%B5%D0%BC%D0%B0/club.md)

Все названия, записи и результаты вымышлены. В работе используются выписки из одного учебного снимка. Время в журналах указано по одной зоне UTC+3, часы синхронизированы по условиям кейса.

## Д1. Паспорт объекта

Клуб «В гостях у троллей» использует личный кабинет для проведения игротек. Ведущий видит список записавшихся на своё мероприятие. По общему паспорту в ИСПДн хранятся иные ПДн 1 200 уникальных совершеннолетних участников, которые не являются сотрудниками оператора. Признаки ГИС и объекта КИИ в легенде отсутствуют.

Пользователи работают с корпоративных ноутбуков. Управляемое устройство зарегистрировано в корпоративной системе управления и соответствует её требованиям. VPN-шлюз принимает соединения извне. После входа ведущий открывает кабинет, а сервер портала сам подключается к PostgreSQL. Сеть управления доступна через администраторский узел-посредник. В область проверки входят каталог учётных записей, сетевые устройства, служебные роли и роли организаторов, серверы и журналы событий.

**Д1‑У. Дополнительная вводная.** Модель угроз учебного оператора относит актуальные угрозы к типу 3. Преподаватель выдаёт этот факт после того, как студенты укажут, каких сведений им не хватает для определения УЗ.

## Д2. Локальные критерии и допуск к VPN

Учебный регламент Л1 допускает сотрудников к VPN с управляемого устройства после многофакторной проверки (MFA). Администраторы входят под отдельной группой. На портале `staff` читает своё расписание, `organizer` работает с записями назначенной игротеки, `admin` отвечает за техническое обслуживание. Доступ через VPN проверяется по матрице Д4. После удаления группы `organizer` привилегии на активном сеансе портала должны прекратиться не позднее чем через 15 минут. У пользователя сохраняется обычная роль `staff`.

| ID | Устройство и учётная запись | MFA | Проверка управляемости | Решение VPN |
|---|---|---|---|---|
| D21 | Корпоративный ноутбук, `staff` | Пройдена | Подтверждена | Допуск |
| D22 | Личное устройство, `staff` | Пройдена | Проверка пропущена | Допуск |
| D23 | Корпоративный ноутбук, `staff` | Отказ | Подтверждена | Отказ |
| D24 | Корпоративный ноутбук, выделенная группа VPN администраторов | Пройдена | Подтверждена | Допуск в контур управления |

## Д3. Роли портала

| ID | Кто и что запрашивает | Критерий Л1 | Наблюдение |
|---|---|---|---|
| P31 | `staff` открывает своё расписание | Разрешить | Расписание показано |
| P32 | `staff` запрашивает список участников чужой игротеки | Запретить | Отказ |
| P33 | `organizer` запрашивает отчёт назначенной игротеки | Разрешить только записи этой игротеки | В отчёте есть строки другой игротеки |
| P34 | `admin` проверяет состояние сервиса | Разрешить просмотр состояния без полей с данными игроков | Показано только состояние сервиса |

Результаты описывают учебные ответы с обезличенными идентификаторами. В протокол включают ID учебных записей и вывод о составе выдачи.

## Д4. Матрица потоков

Стрелка в схеме означает направление начала соединения. Администраторский пул VPN выделен отдельно. F4 и F5 относятся к управлению сервером портала. Прикладная роль БД используется по F3.

| Поток | Источник | Назначение | Целевое правило | Наблюдение |
|---|---|---|---|---|
| F1 | Удалённый клиент | VPN-шлюз, TCP/443 | Принимать внешний вход, допуск после MFA и проверки устройства | См. D21–D24 |
| F2 | Пул VPN сотрудников | Кабинет ведущего, HTTPS/443 | Разрешить | Портал доступен |
| F3 | Сервер портала | PostgreSQL, TLS/5432 | Разрешить служебной роли | Тестовое подключение проходит |
| F4 | Пул VPN администраторов | Узел-посредник, SSH/22 | Разрешить | SSH доступен |
| F5 | Узел-посредник | Сервер портала, SSH/22 | Разрешить обслуживание | SSH доступен |
| F6 | Пул VPN сотрудников | PostgreSQL, TCP/5432 | Блокировать | TCP проходит. Допуск к БД не проверялся |
| F7 | Пул VPN сотрудников | Узел-посредник, TCP/22 | Блокировать | Фильтр блокирует |

## Д5. Межсетевой экран и комплект документов

| ID | Материал | Исходные сведения |
|---|---|---|
| D51 | Выписка из правил | Перед правилом запрета доступа к БД размещено широкое разрешающее правило R40 для пула VPN сотрудников. В учебном фильтре применяется первое совпавшее правило |
| J56 | Событие фильтра | Для F6 сработало R40, действие `allow`, результат совпал с наблюдением в Д4 |
| D52 | Карточка поставщика | Документ относится к версии 4.2. Установлена 4.3. Формуляр на установленное исполнение и документы об охвате обновления отсутствуют. Наименование «Учебный экран» условное |

Для повторной оценки нужно подтвердить запрет F6, сохранение F2 и F3 и зарегистрировать срабатывание правила. По версии 4.3 требуется документальное подтверждение области применения.

## Д6. Журналы отзыва роли организатора

Обращение H42 относится к ведущему, которого сняли с подготовки игротеки. Он теряет только роль организатора `organizer`. Идентификатор этой учебной учётной записи — `U17`.

| Время | Источник | Событие |
|---|---|---|
| 09:54 | Портал | `U17` создал сеанс `S17` с ролью `organizer` |
| 10:00 | Каталог учётных записей | Группа `organizer` для `U17` удалена по H42 |
| 10:22 | Журнал портала | `U17` в сеансе `S17` открывает список участников. Решение `allow` |
| 10:25 | Журнал портала | Новый сеанс `S18` для `U17` получает только `staff`. Просмотр своего расписания проходит |

Для заключения сопоставляют пользователя, идентификатор обращения, время и сеанс. Отдельно записывают критерий для отзыва прав организатора в старом сеансе и критерий для сохранения базовой роли.
