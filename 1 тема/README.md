## Почему выбрана эта тема

Заявка с именем, телефоном и электронной почтой проходит через несколько зон. Шлюз принимает запрос, приложение обрабатывает его, а PostgreSQL хранит заявку. Ошибка на любом участке может привести к раскрытию данных. Даже при исправном TLS приложение может записывать контакты в журнал, а лишнее сетевое правило может открыть порт БД. На этом примере видно, какую часть защиты обеспечивает каждый компонент и какими фактами это можно подтвердить.

**Объект исследования** — сетевая информационная система персональных данных (ИСПДн) частного оператора. **Предмет** — защита сетевых потоков, узлов, приложения и хранилища, через которые проходит заявка. **Цель** — научиться выбирать применимые требования, проверять выполнение сетевых мер и оформлять вывод с доказательством и пересмотром после исправления.

## Просмотр слайдов

Файлы с окончанием `.marp.md` читаются на GitHub как Markdown. Для показа слайдов откройте файл в редакторе с поддержкой Marp. Marp CLI также экспортирует слайды в HTML и PPTX. [Документация Marp CLI](https://github.com/marp-team/marp-cli)

Выполните из каталога «1 тема». Аналогично можно экспортировать любую лекцию из `lectures/`.

```sh
npx @marp-team/marp-cli presentation.marp.md -o presentation.html
npx @marp-team/marp-cli --pptx presentation.marp.md -o presentation.pptx
```
